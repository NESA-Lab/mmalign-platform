# 书生 Intern-S2 推理时对齐方法评测报告（用方法 vs 不用方法）

## 评测设置

- 被测模型：书生 Intern-S2-Preview-35B（Intern 官方 API `intern-s2-preview-35b`，temperature 0，关闭思考；zero_think / more_think 按 test3 适配原生控制思考模式）。
- 方法代码：mmalign 主包 + `test/test3` 书生适配包（保留图片、透传思考开关）。方法改动见本 PR（overrefusal_check / self_refine 修复，安全防御的 `use_specs` 等选项与 `*_spec` 配置）。
- 评测集：MMAlign 多模态价值观安全评测集、多模态场景规约对齐评测集（各包自带的评审提示与指标）。
- 评审：gpt-5.6-luna（经中转站）。基线 `raw`：直接把原始图文请求交给书生模型，不使用任何方法。
- 方法可见场景规约（与 SpecBench 协议一致）；任何方法都不接触评审结果。
- **调参只在开发集上进行**（138 条，JailGuard 校准时另抽，与测试集不重叠）；方法定版后在测试集（230 条：价值观安全 180 + 场景规约对齐 50）上做最终对比。
- 表中数字为“所有方法都成功作答并被评审的共同子集”上的规约通过率（YES/(YES+NO)），Intern API 拦截的样本不计入；Δ 为相对 raw 的差，95% 置信区间来自配对 bootstrap（2000 次）。
- 未评：`ipr_prompt_refine`（文生图提示词改写，不适用于问答评测）。`best_of_n`、`tpo` 未配置奖励模型，使用平台内置的简单打分规则。

## 结论

1. **场景规约对齐集**：21 个最终方法全部显著优于不用方法（+12.6～+25.9 分，置信区间全在 0 以上）；最好的 `more_think` 85.6、`align3_specbench` 85.3（raw 59.7）。
2. **价值观安全集**：raw 本身已有 87.3，提升空间小。9 个方法显著提升（`align3` 93.7、`overrefusal_check` / `critic_revise_agent` 93.4、`more_think` 93.1 等），其余 12 个为正向但置信区间跨 0，不能宣称显著。
3. **jailguard（原版，仅校准阈值）在价值观安全集上显著下降（−6.0）**，规约增强版 `jailguard_spec` 则在两个集上都为正向（+3.1 / +18.4）。
4. 6 个通用防御方法的**原版**（不读规约）在测试集上基本不提升或下降（见下方附表）；它们的提升来自规约增强。规约增强版与 `vanilla`（只给规约）相比差距不大，说明这类方法的增益主要来自场景规约本身，防御逻辑本身的额外贡献有限。

## 局限

- 样本量有限：价值观安全集共同子集 90 条、场景规约集 31 条；置信区间较宽。
- Intern API 对部分危险请求直接拦截，拦截样本不进入分母。
- 评审为单一 LLM 评审（gpt-5.6-luna），未做人工复核。
- `best_of_n` / `tpo` 未接真实奖励模型。

## 复现

样本编号、逐方法汇总指标和置信区间保存在 `test/test3/results/intern_method_uplift/`（`{dev,test}_<评测集>_sample_ids.json`、`test_summaries.json`、`bootstrap_vs_raw.json`）。评测脚本为 `test/test3/scripts/eval_spec_aware.py`（依赖同目录的 `eval_methods_common.py`），用法见脚本开头的说明；需要在环境变量中设置 Intern API 与评审接口的密钥，脚本本身不包含任何密钥。
